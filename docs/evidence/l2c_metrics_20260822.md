# L2C 현재 버전 검증 기록

측정 코드는 커밋 `04a2783ce01e394f2df41b4099c0db939a0636c3`의 변경 작업
트리이며 설정 지문은 `eb801d14ed07`이다. 사용 모델은
`gemini-3.5-flash-lite`, `gemini-3.6-flash`이다. 수집 시험은 각 시나리오를
빈 공고 DB에서 시작했다.

## 지표 이름

| 표시 이름 | 판정 기준 |
|---|---|
| 실제 공고까지 확인한 수집 성공 | 목표와 관련된 공고 상세 화면, 회사명, 공고명과 URL을 사람이 확인하고 DB 저장까지 완료 |
| 시스템 자동 검사 통과 | 목표 수, 저장 수, 상세 URL과 필수 필드 존재 여부를 코드가 확인 |
| 저장된 행동 사용 | 자율탐색에서 저장하고 검토한 행동 경로를 다음 실행에서 선택 |
| 저장된 행동을 끝까지 실행 | 선택한 행동 경로의 모든 물리 행동과 사후 화면 확인을 완료 |
| LLM 판단 없이 실행한 행동 수 | 저장된 경로가 직접 실행한 클릭, 입력, 키 입력 등의 물리 행동 수 |
| 저장된 행동 중단 후 LLM 탐색으로 전환 | 저장된 경로 실행 중 화면 조건이 맞지 않아 자율탐색으로 넘긴 횟수 |

## 5개 사이트 수집

서로 다른 검색어 15개를 사이트별 3개씩 실행했다. 같은 행렬을 두 번 실행한 결과
자동 수집 성공은 1차 `12/15`, 근거 필드 보존 재실행 `14/15`로 달랐다. 두 실행의
합계는 `26/30(86.7%)`이다. 실행 사이에 수집 행동 로직은 바뀌지 않았으므로 이 차이는
현재 시스템의 비결정성을 보여준다.

재실행에서 자동 검사를 통과한 14건은 상세 화면, 누적 OCR과 DB 저장값을 전부
대조했다.

| 사이트 | 실제 공고까지 확인한 수집 성공 | 시스템 자동 검사 통과 |
|---|---:|---:|
| 원티드 | 3/3 | 3/3 |
| 사람인 | 3/3 | 3/3 |
| 잡코리아 | 3/3 | 3/3 |
| 고용24 | 2/3 | 2/3 |
| 로켓펀치 | 3/3 | 3/3 |
| 합계 | **14/15 (93.3%)** | **14/15 (93.3%)** |

재실행 15회는 총 `934.30초`, `1,285,207토큰`, 추정 비용 `$0.706876`을
사용했다. 실행당 평균은 `62.29초`, `85,680토큰`, `$0.047125`이다. 자동 수집에
성공한 14회만 계산하면 평균 실행시간은 `54.21초`, 화면 판단은 `10.14회`, OCR은
`8.00회`, 토큰은 `73,772`, 추정 비용은 `$0.037805`이다.

실패 1건은 다음 단계에서 발생했다.

| 시나리오 | 실행시간 | 직접 원인 |
|---|---:|---|
| 고용24 `생산 관리` | 175.37초 | 첫 공고와 보충 공고 모두 필수 자격요건을 확보하지 못해 거절된 뒤 같은 후보에 다시 진입했고, 화면 판단 32회와 OCR 21회 후 판단 한도에 도달 |

실패까지 포함한 실제 지출을 자동 수집된 공고 14건으로 나누면 공고 1건당
`91,801토큰`, `$0.050491`이다. 아래 필드 감사까지 통과한 12건으로 나누면
`107,101토큰`, `$0.058906`이다.

## 저장된 행동 재사용

원티드 5개와 사람인 5개 검색어를 대상으로 `자율탐색 → 행동 검토·저장 → 경험
기반 탐색` 순서로 실행했다.

| 단계 | 결과 |
|---|---:|
| 자율탐색 수집 성공 | 10/10 |
| 행동 검토·저장 성공 | 9/10 |
| 실제 경험 기반 탐색 실행 | 9회 |
| 저장된 행동 사용 | 9/9 |
| 저장된 행동을 끝까지 실행 | 9/9 |
| LLM 판단 없이 실행한 물리 행동 | 18회 |
| 저장된 행동이 대체한 원래 LLM 판단 | 9회 |
| 저장된 행동 중단 후 LLM 탐색으로 전환 | 0회 |
| 경험 기반 탐색의 전체 수집 성공 | 8/9 |

저장된 경로는 검색어 입력과 Enter 입력을 한 묶음으로 실행했다. 사람인 DevOps는
행동 검토 단계가 첫 원본 행동을 누락해 저장 계약을 통과하지 못했으므로 경험 기반
탐색을 시작하지 않았다. 사람인 Java는 저장된 검색 행동을 끝까지 실행했지만 이후
가변 카드·상세 화면 자율탐색에서 회사 정보 화면으로 이동해 전체 수집에 실패했다.

두 실행 모두 수집에 성공한 8쌍만 같은 분모로 비교한 결과는 다음과 같다.

| 지표 | 자율탐색 평균 | 경험 기반 탐색 평균 | 변화 |
|---|---:|---:|---:|
| 실행시간 | 52.15초 | 49.28초 | -5.5% |
| LLM 화면 판단 | 8.38회 | 7.00회 | -16.4% |
| OCR | 7.25회 | 5.63회 | -22.4% |
| 토큰 | 62,946 | 54,606 | -13.2% |
| 추정 비용 | $0.034200 | $0.035108 | +2.7% |

저장된 행동은 고정 검색 구간의 LLM 판단을 줄였다. 상세 화면의 모델 전환과 응답
지연이 실행마다 달라 비용과 실행시간 개선은 일관되지 않았다. 8개 행동 경로의
일회성 검토·저장에는 별도로 `199.63초`, `156,146토큰`, `$0.428061`이 들었다.
수집 실행 지표와 이 후처리 비용은 분리해 계산한다.

## DB 근거 답변

같은 질문을 공고 152건이 있는 DB와 빈 DB에 각각 실행했다.

> 웹 수집은 하지 말고 현재 DB에서 AI 에이전트 관련 공고를 찾아 주요 업무와 요구
> 기술을 근거와 함께 정리해줘.

| DB 상태 | 결과 |
|---|---|
| 공고 152건 | 웹 수집 없이 관련 공고 16건을 답변에 사용하고 16개 공고 ID를 인용했다. 인용 ID는 모두 DB에 존재했고 실행 전후 행 수는 152건으로 같았다. 실행시간 `44.77초`, `40,641토큰`. |
| 빈 DB | 웹 수집과 인용을 만들지 않고 근거가 없어 답변할 수 없다고 밝혔다. 실행 전후 행 수는 0건이었다. 실행시간 `15.09초`, `6,058토큰`. |

공고가 있는 시험은 기능 계약을 모두 만족했지만 임시 토큰 상한 `40,000`을
`641토큰` 초과했다. 따라서 답변 근거 사용은 통과했고 토큰 예산은 실패했다. 빈 DB
답변의 “0건으로 수집되어”라는 문장은 실제로 수집을 실행하지 않았으므로 문구 수정이
필요하다.

## 사람 대비 정리 시간

사용자가 직접 공고를 검색하고 회사명, 공고명, URL, 주요 업무와 자격요건을 정리하는
시간을 공고 1건당 약 `5분`으로 추정했다. 같은 결과 계약으로 핵심 필드가 모두
맞은 12건을 기준으로 비교했다. L2C 시간에는 실패 1건과 필드 감사에서 탈락한 2건의
실행시간도 포함했다.

| 지표 | 사람 추정 | L2C 재실행 |
|---|---:|---:|
| 검증된 결과 12건 확보 시간 | 60.00분 | 15.57분 |
| 검증된 결과 1건당 시간 | 300.00초 | 77.86초 |
| 시간당 검증된 결과 | 12.00건 | 46.24건 |
| 시간 차이 | - | **3.85배 빠름, 74.0% 감소** |

12건 기준 추정 절약 시간은 `44.43분`이다. 사람 쪽 수치는 한 사용자의 경험 추정이며,
여러 참가자가 같은 공고를 처리한 통제 실험 결과는 아니다.

## 이번 결과로 사용할 수 있는 문장

1. 빈 DB에서 5개 채용 사이트와 같은 15개 검색어를 두 번 실행해 자동 수집
   `26/30(86.7%)`를 기록했다. 두 실행은 `80.0%`와 `93.3%`로 달라 비결정성도
   함께 확인했다.
2. 현재 버전이 자동 수집한 14건을 전수 대조해 핵심 필드가 모두 맞은 결과
   `12/14(85.7%)`, 전체 시도 대비 `12/15(80.0%)`를 확인했다.
3. 직접 검색·정리 1건당 5분이라는 사용자 추정과 비교하면, 실패와 품질 탈락 비용을
   포함한 L2C의 검증 결과 1건당 시간은 `77.86초`로 `3.85배` 빨랐다.
4. 경험 기반 탐색 9회 모두 저장된 검색 행동을 끝까지 실행했고, 물리 행동 18회와
   연결된 LLM 판단 9회를 호출 없이 처리했다.
5. 두 방식 모두 수집에 성공한 8쌍에서는 평균 화면 판단 `16.4%`, OCR `22.4%`,
   토큰 `13.2%`가 줄었다. 모델 전환 비용 때문에 평균 추정 비용은 `2.7%` 늘었다.
6. DB 전용 질문은 웹 수집 없이 16개 공고를 인용했고, 빈 DB에서는 근거와 인용을
   만들지 않았다.

## 남은 검증

- 서로 다른 사용자 3명 이상이 같은 출력 계약으로 직접 정리한 시간을 재서 5분 추정
  기준을 교체한다.
- 고용24에서 자격요건이 없는 공고를 거절한 뒤 같은 후보에 재진입하는 흐름을 수정하고
  `생산 관리` 실패 지점만 재검증한다.
- 회사명 철자 보존과 필수 경력 누락을 품질 평가 데이터셋에 추가한다.
- 사람인 DevOps의 행동 검토 누락과 사람인 Java의 저장 행동 이후 자율탐색 실패를
  각각 분리해 재검증한다.
