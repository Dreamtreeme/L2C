# 초기 비전 자동화 실험 기록

이 문서는 현재 구현에서 제거된 실험과 그 판단 근거만 보존한다. 현재 동작과 장애 대응은 [`troubleshooting.md`](../../troubleshooting.md), 현재 런타임 버전은 [런타임 호환 기준](../runtime_compatibility.md)을 따른다. 세부 로그와 당시 코드는 Git 이력에서 확인한다.

## 폐기하거나 대체한 접근

| 접근 | 확인한 문제 | 현재 처리 |
|---|---|---|
| 로그인 화면 자동 복구 | 로그인 필요 여부를 코드가 일반화할 수 없고 사용자 계정 작업까지 자동화 범위가 넓어짐 | 로그인·CAPTCHA는 사용자가 처리하고 수집 작업은 로그인 없이 접근 가능한 범위에서 실행 |
| Ollama 로컬 VLM의 JSON 도구 호출 | 작은 모델이 스키마를 자주 깨뜨리고 긴 개행·잘못된 좌표를 반환 | 화면 판단 모델은 구조화 도구 호출을 안정적으로 지키는 외부 모델 사용 |
| Qwen 계열 로컬 VLM 좌표 직접 출력 | 이미지 좌표 정합성과 응답 지연이 실제 GUI 조작 기준을 충족하지 못함 | OmniParser와 PaddleOCR가 화면 요소를 마커화하고 모델은 허용된 마커를 선택 |
| UI 요소 상위 8개만 전달 | 검색 결과 카드와 하단 컨트롤이 입력에서 누락 | 고정 개수 휴리스틱을 제거하고 화면 관찰 결과를 구조화해 전달 |
| Hugging Face 모델 직접 구동 | 속도 향상 추정만 있었고 동일 장비·동일 화면 실측 근거가 없었음 | 구현하지 않음 |
| OmniParser 아이콘 캡션 모델 | 캡션 생성 비용에 비해 클릭 정확도 개선이 작았음 | 상자 검출과 OCR만 사용하고 의미 판단은 화면 추론 모델이 담당 |
| 전체 화면 OCR 텍스트 병합 | 입력 토큰은 줄었지만 섹션 경계와 상세 정보가 손실됨 | 상세 화면은 누적 OCR 버퍼와 공고 검토 계약으로 처리 |
| `state_key`와 OCR 문자열 Jaccard | 같은 화면도 동적 텍스트와 OCR 순서 때문에 키가 흔들렸음 | 활성 경험 경로는 `site + task_category`, URL 범위, ROI 화면 서명으로 조회·검증 |
| 전체 화면 pHash | 배너·이미지·목록 내용 변화에 민감해 같은 UI 구조도 불일치 | 대상 주변 ROI pHash를 행동 시작점 검증에 사용 |
| OCR 마커 ID 재사용 | 마커 ID는 OCR 실행마다 다시 부여돼 지속 식별자가 될 수 없음 | 저장한 대상 비율과 ROI 화면 서명을 사용하고 불일치 시 자율 판단으로 복귀 |
| 원자 행동별 레시피 | `입력 -> 제출` 문맥이 끊기고 같은 목적의 중복 레시피가 쌓임 | 한 성공 실행의 연속 전이를 `ExperienceRule` 하나로 저장 |
| 요청 안에서 Critic 자동 승격 대기 | 수집은 끝났지만 HTTP 요청과 E2E가 Critic 완료를 기다리며 멈춤 | 후보를 SQLite 대기열에 저장하고 별도 승격 작업자가 비동기로 검토 |
| 요청 횟수 기반 OCR 작업자 재시작 | 장시간 실행을 안정화하지 못했고 정상 초기화 비용만 반복 | 작업자를 계속 재사용하고 실제 timeout·프로세스 실패 때만 재시작 |

## 런타임 전환 이력

초기 구현은 Python 3.10과 PaddleOCR 2.6.2 조합에서 시작했다. PaddleOCR 전체 화면 입력이 간헐적으로 오래 멈추는 현상을 계측한 뒤 PaddleOCR 3.x API로 전환했고, 앱과 OCR 의존성을 각각 `.venv-app`, `.venv-ocr`로 분리했다. 이후 Python 3.13과 PaddlePaddle GPU 3.3.1 조합으로 다시 검증했다.

구버전에서 사용한 `PaddleOCR(..., use_gpu=...)`, `ocr.ocr(..., cls=False)`, CUDA 11.8 전용 설정은 현재 코드의 기준이 아니다. 설치와 호환성 판단에는 [런타임 호환 기준](../runtime_compatibility.md)만 사용한다.

## 과거 성능 수치의 해석

원티드 반복 수집에서 약 200초가 약 105초, 이후 약 61초까지 줄어든 실행이 있었다. 검색어, 대상 공고, 사이트 상태, 모델 응답과 코드 버전이 고정되지 않았으므로 이 값은 현재 성능 기준선으로 사용하지 않는다.

현재 경험 기반 탐색은 실행시간 한 번의 차이보다 다음 지표로 평가한다.

- 같은 고정 대상 계약에서 수집 결과와 출처가 모두 유효한가
- 저장된 경험 경로가 시작되고 끝까지 완료되는가
- 자율 판단 호출을 몇 회 순감소시켰는가
- 재생 실패가 즉시 자율 판단으로 복귀하는가
- 추가된 검증·해석 호출까지 포함해 토큰과 비용이 실제로 감소하는가

현재 재현 절차와 수치는 [제품 데모 및 검증](../product_demo.md), 측정 정의는 [E2E 관측 환경](../e2e_observability.md)에 기록한다.
